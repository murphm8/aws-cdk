## Current Task: AWS PCS Cluster Default Values Removal

### Status: Complete

Successfully updated the AWS PCS cluster L2 construct to remove all defaults and align with CloudFormation template requirements.

### Just Completed
- **Analyzed CloudFormation Documentation**: Referenced AWS::PCS::Cluster template to identify required vs optional properties
- **Updated ClusterProps Interface**: Made required properties non-optional:
  - `subnets`: Now required (was optional with default)
  - `securityGroups`: Now required (was optional with auto-creation)
  - `size`: Now required (was optional with SMALL default)
  - `scheduler`: Now required (was optional with Slurm default)
- **Removed Constructor Defaults**: Eliminated all fallback logic and default value assignments
- **Maintained Optional Properties**: Kept nullable properties that match CloudFormation:
  - `clusterName`: Optional (auto-generated by CloudFormation if not provided)
  - `slurmConfiguration`: Optional
  - `tags`: Optional

### Key Changes Made

#### Interface Updates
```typescript
// Before: Optional with defaults
readonly subnets?: ec2.SubnetSelection;
readonly securityGroups?: ec2.ISecurityGroup[];
readonly size?: ClusterSize;
readonly scheduler?: SchedulerConfiguration;

// After: Required properties
readonly subnets: ec2.SubnetSelection;
readonly securityGroups: ec2.ISecurityGroup[];
readonly size: ClusterSize;
readonly scheduler: SchedulerConfiguration;
```

#### Constructor Simplification
- Removed security group auto-creation logic
- Removed subnet default selection fallback
- Removed scheduler configuration defaults
- Removed cluster size default assignment
- Now directly uses provided properties without fallbacks

### CloudFormation Alignment
The L2 construct now perfectly mirrors the AWS::PCS::Cluster CloudFormation resource:
- **Required in CFN**: `Networking`, `Scheduler`, `Size` → **Required in L2**
- **Optional in CFN**: `Name`, `SlurmConfiguration`, `Tags` → **Optional in L2**

### Impact on Users
- **Breaking Change**: Users must now explicitly provide all required configuration
- **Benefit**: No more inappropriate defaults that might not suit user's environment
- **Clarity**: Interface clearly shows what's required vs optional
- **Consistency**: Matches underlying CloudFormation behavior exactly
